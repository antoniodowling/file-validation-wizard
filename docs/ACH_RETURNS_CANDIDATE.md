# Ordinary network ACH Returns and COR candidate

Implemented 2026-10-14 as a local public-source candidate. This is standalone network ACH, admitting ordinary returns of CCD/PPD/CTX/WEB/TEL and administrative COR notifications. It does not establish bank, hosted, original-file, business-fixture or Production acceptance. Specialized layouts are gated individually; ordinary supported entries can be evaluated.

## Candidate behavior and remaining gates

The parser shares only fixed-record framing, slicing, calendar/routing helpers and BigInt totals with origination. Checks aggregate repeated violations by rule with a first exact source location and bounded counts. Framing/ASCII/order failures stop dependent checks. Missing numeric arithmetic operands suppress reconciliation; conditional checks are not applicable only when their prerequisite context establishes absence. Partial batch evaluation must not manufacture a file-wide passed check.

Records use consistent LF, CRLF, CR or complete concatenation; an optional terminal separator is allowed. BOM, mixed framing, blank records, tabs and non-ASCII fail. Header/detail/control fields retain exact offsets. Padding forms blocks of ten. Counts include both detail and addenda; hashes sum the eight-digit receiving institution prefixes modulo ten billion. Date interpretation is2000–2099. No holiday or origination-weekend warning applies.

Returns allow numeric zero amounts, covering returns of prenotes/nonmonetary entries. COR amounts are zero. Exactly one exception addenda follows each entry, with indicator1; CTX declared count must be numeric. A synthetic0001 count is valid, but another numeric retained count is not rejected on an unqualified preservation/coherence assumption. The full addenda trace80–94 equals the current detail trace. Original trace7–21 and RDFI28–35 are separate references, without original-file comparison. Ordinary99 death-date22–27 is optional and only permitted for R14/R15. R17 information36–79 must be populated; its legitimacy and purpose-dependent semantics are excluded. COR98 reserves22–27 and65–79, with corrected data36–64 following the code grammar.

Service200/220/225 and actor status1/2 are admitted as a candidate assumption; actor identity is unverified. Service280 is accounting advice, not an ordinary COR requirement. An isolated COR entry does not identify the original SEC, so it uses the administrative22-character name field without claiming preservation of an original CTX layout.

**Directional control arithmetic:** Nacha generic totals definitions, Treasury explicit return families and Moov primary implementation corroboration establish credit21/31/51 and debit26/36/56 assignment. Entry-to-batch cents and file-to-declared-batch totals use exact BigInt, with numeric operand prerequisites. COR amounts and corresponding totals are zero. Missing arithmetic operands suppress reconciliation rather than manufacturing PASS.

**CTX count preservation/coherence remains unresolved.** Historical2018 operator edits require actual-count equality, but current Moov primary implementation explicitly exempts CTX return replies and preserves the original declared count. The2023 educational mapping contains an editorial trace/count error. Candidate checks numeric count only and exactly one actual exception addenda, with no original-count preservation or actual-count coherence claim. This conflict remains an explicit exclusion requiring current normative qualification.

**Unsupported without a format verdict:** dishonoredR61/R62/R67–R70; contestedR71–R77; refused-CORC61–C69; C08(IAT-only) and C14 outside qualified correction contracts; other SEC layouts. These gates do not hold the entire format pack. R69 error-field syntax and R73 conditional dates must wait for exact specialized positions. Unknown/unassigned reason/change codes such asR99/C04 fail the known field's vocabulary check. The implementation uses explicit sets, never invented continuous R/C ranges.

No collection, sharing, retention, authentication or logging changes are introduced. Input fixtures are synthetic, and metadata deliberately excludes original preservation, account/directory existence, authorization, identity, MAC authentication, deadlines and actual settlement.
